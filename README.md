## 一、行业背景与真实痛点

> 本节数据来自一线旅行社定制师调研（问卷 + 线下访谈）。

2025 年全国出入境 **6.97 亿**人次创历史新高，其中免签入境外国人 **3008 万**人次、同比增长 **49.5%**；其中相当比例的游客会通过 Trip.com 对接平台认证的旅行定制师。

行业的缺口不在教材，而在**具备入境游定制能力的从业者**。当前定制师的认证方式为线上课程加一次电话面试，实际培养仍以师傅带教、以真实客户练习为主：新人入职前 3 个月通常无法独立创造价值，人力成本持续投入；而平台派单存在硬性时限——**1 小时内必须致电客户、4 小时内必须上传方案**，新人难以独立承接。行业需要的是一个可以安全试错的训练环境。

### 入境游定制比一般定制游难在四层叠加

```mermaid

  L["语言层<br/>跨语种沟通"] --> C["文化层<br/>宗教 · 饮食 · 礼仪 · 隐私"]
  C --> P["政策层<br/>免签 · 过境 · 口岸 · 时效"]
  P --> F["履约层<br/>跨境支付 · 多语种地接 · 涉外用车"]
```

| 层次 | 主要难点 | 系统内的考核方式 |
| --- | --- | --- |
| 语言层 | 英语之外还有日语、韩语、泰语、西语、阿语等，语音与文字都要跨语种 | 15 门语言的客源可生成，客户在语音与群聊里**始终说自己那门语言** |
| 文化层 | 宗教、饮食、礼仪、作息、隐私边界，一句话说错就可能是投诉甚至涉外舆情 | 国别文化红线进 Rubric 与语义拦截网 |
| 政策层 | 免签与过境免签、入境口岸、签证时效随时变动，直接决定行程是否可行 | 签证/证件核验进交付物校验与评分点 |
| 履约层 | 跨境支付、多语种地接、涉外酒店与用车、境外保险，链条比国内游长 | 地接社/酒店/车队/票务/司导五类资源方 Agent + 结算台账 |

## 二、解决方案

| 行业痛点 | 对应做法 |
| --- | --- |
| 新人缺少真实接单环境 | 把真实接单的**输入物**仿真出来：派单卡片、客户电话、供应商回执、突发通知 |
| 训练后缺少专业点评与错误反馈 | 按真实**交付物**（需求单、行程方案、报价单、合同与保险、出团通知书、结算单）逐项评分，并生成讲义与学习规划 |
| 能力评价依赖师傅主观判断，缺乏量化标准 | 用**掌握度**把能力变成看得见的数字，把师傅从重复答疑中解放出来 |

## 三、价值测算

![培养周期与单人成本](docs/charts/value-cost.png)

![师傅工时释放](docs/charts/value-hours.png)

- **单个新人**：调研显示，新人入职 1–3 个月通常只能承接简单订单，师傅繁忙时缺少可及的指导。若将 4 个月的纯投入期缩短 30%（约 1.2 个月），按综合人力成本 8,000 元/月计算，**单个新人可节省培养成本约 1 万元**。
- **师傅工时**：师傅每天约 1 小时用于重复答疑，若其中 60% 由系统承接，**每人每年可释放约 150 小时工时**。
- **对旅行社**：按每年招 5 名新人计算，**年节省约 5 万元量级**——对入驻携程的小微旅行社商户有吸引力。

![四类真实损失场景](docs/charts/loss-scenes.png)

线下访谈记录了四类真实损失场景：漏算保险与停车费导致亏损、酒店超售临时换房引发客户不满、车辆故障导致临时调度、高铁票不足只能多购一站作为补偿。这些高频错误均可在上岗前于系统中反复演练，**无需由真实客户承担试错成本**。

## 四、智能体协同：把幻觉挡在门外

评分、出题与学习资料生成均不依赖单个模型的自由发挥：由编排管家统一调度，经**六帽并行审查**（白帽查事实、黑帽查逻辑、蓝帽总控等）后输出；未通过审查的内容会打回重做，不会直接呈现给学员。

## 五、技术亮点

### 5.1 三条主线能力

| # | 能力主线 | 具体实现 |
| --- | --- | --- |
| 1 | **全链条双向仿真** | 输入物（派单卡片、客户通话、供应商回执、平台与突发事件通知）与输出物（需求确认单、行程方案、分项报价、合同与保险、出团通知书、结算核对单）双向仿真，学员产出的是可交付的工作物，而非答题结果 |
| 2 | **多智能体协同抑制幻觉** | 编排管家调度、六帽并行审查、未通过即打回重做；资源方 Agent 仅依据本单客观事实作答，不会为迎合学员而虚构报价或档期 |
| 3 | **个性化生成与动态难度** | 答错时降维解释并做同题重做，答对后提升难度档位；掌握度分 M1–M5 五档，M1 以补救为主、M2–M5 逐档加压，难度参数由画像直接驱动 |

### 5.2 其他技术亮点

| 亮点 | 机制 |
| --- | --- |
| **证据链锚定的原子评分** | 61 个技能点逐个给分，每一分都必须引用学员原话或交付物片段作为证据坐标，可回放、可反查 |
| **双层拦截网** | 第一层确定性校验（分项加总、毛利率、保险项、日期自洽等算术与字段检查），第二层语义合规红线（宗教饮食、证件入境、支付可行性、行程内部矛盾）；命中红线的交付物无法投递 |
| **覆盖校验** | 依据 Rubric 埋点核对本单实际考核到的技能点；未考核到的技能点**不更新画像**，避免未考核即提升掌握度 |
| **画像 ↔ 难度闭环** | 复盘结果写回画像 → 下一单的目标技能点、派单残缺度、时限、情绪、预置突发事件全部由画像反推，形成可追溯的闭环 |
| **15 门语言 / 23 个客源市场** | 客户人设、语言、音色三者同源：人选、语种、声音一一对应，客户全程只说自己那门语言 |
| **真实外部数据** | 高德地图与路线（含途经点与公交换乘明细）、Open-Meteo 天气、实时汇率，全部走真实接口并落库 |

#### 6.3.0 平台界面与接单流程仿真

接单环节还原携程定制游工作台（vbooking）的界面与流程：左侧为通知分类（重要通知、订单通知、定制游待接单通知、度假 / 邮轮 / 玩乐订单通知、产品通知、财务通知等），右侧为待接单卡片，展示需求单号、目的地、客源语言、首呼倒计时与同期竞争人数。

抢单成功后进入订单管理，并可打开订单详情查看平台字段：提交时间、需求单号、客户与客源地、服务语言、入境证件、用户信息备注、订单跟进信息与企业合规提示，以及产出与投递（8 类交付物的投递状态）。

订单详情集中展示客户背景、服务语言、入境证件与派单信息；右下角进度条可展开，查看 13 步的当前进度与**本步完成条件**。

在资源大群中向地接社、酒店、车队与票务询价。资源方 Agent 仅根据本单客观事实（报价、库存、档期）作答；需求未经确认时不会给出确定报价，以避免学员将未确认资源对外报价。

分项报价单逐项列出导游、用车、住宿、餐饮、门票、保险与服务费；提交前先经确定性算术校验，核对分项合计、毛利率与保险项。

#### S8 · 成交确认与系统录单
客户确认方案后提交合同与保险。保险属于必填合规项，缺失或与其他安排冲突时会被双层拦截网拦截。

#### S9 · 资源锁定与行前准备
出团通知书用于锁定资源，并同步至客户群与地接群；行前阶段司导会就饮食禁忌、接机时间等要素反向确认，用于考核行前要素的覆盖度。

<img src="docs/demo/s9-notice.gif" width="880">

行中突发事件由导演 Agent 直接发入对应工作群（车辆故障、酒店超售、票务变化等）。正确处理顺序是先行安抚客户、同时并行协调资源；顺序有误将直接影响应急解决维度的评分。

<img src="docs/demo/s10-incident.gif" width="880">

#### S11 · 行后结算与回访
成本与结算台账：逐项核对地接结算单与实际成本，处理赔偿与追偿，结账留档并计算该订单的实际利润。

<img src="docs/demo/s11-settle.gif" width="880">

#### S12 · 复盘评分与个性化补救
61 个技能点逐项评分，每一分都带证据坐标；评分结果写回画像，决定下一单的难度参数与待补强技能点。

<img src="docs/demo/05-score.gif" width="880">

#### 6.3.14 工具查询与评分核验（真实接口）

实战所需的外部数据均来自真实接口调用：路线规划（高德，含途经点、驾车/步行/骑行/公交与耗时）、天气预报（Open-Meteo + 高德地理编码）、实时汇率（open.er-api.com），以及行程绕路与折返核验。

评分环节通过服务端接口调用评分 Agent：输出各技能点得分与平均分，同时给出**覆盖校验**（本单实际考核到的技能点、覆盖度与未覆盖项、并可直接跳转补考）与**校准基线**状态。覆盖度不足或校准未达标时，本次结果不会写入画像。

## 七、人工校准集：评分可信度如何保证

自动评分的核心风险是分数漂移。系统通过一套**人工校准集**约束评分 Agent：

- **样本来源**：从真实演练中挑选已人工标注 M 档、并标出证据坐标的样本；
- **覆盖要求**：覆盖 21 个技能点、M1–M5 全档位、9 个客源与中文/英文两种语言，并保留档位边界的难例；
- **校准方式**：每次调整评分提示词或 Rubric 锚点后运行校准，比对 M 档一致率与证据准确率，并重复两轮考察稳定性；
- **准入规则**：阈值取最保守档位（置信度与边界容差）；**未通过校准的评分 Agent 不参与主链**，且未达标时画像只允许下调、不允许上调。

## 八、MCP 接口契约：为平台数据对接预留

外部数据与资源方能力统一按 **MCP 工具契约**（http-jsonrpc，`POST /mcp`）暴露，当前共 11 个工具，覆盖天气查询、路线规划、行程顺序核验、实时汇率、资源询价、交付物投递、拦截网校验、导演事件、订单状态、覆盖校验与知识点检索。

实现层目前使用模拟资源方与公开 API；接入真实供应商时仅需替换实现，契约与上层流程保持不变。**希望未来携程以及更多企业平台提供数据对接支持**（房态、车况、票务档期、结算单等），使训练环境与企业真实业务系统同源。

## 十、本地一键运行

两个入口启动的是**同一套服务**（后端 18010 + 前端 5180），可按使用习惯选择：

| 入口 | 效果 |
| --- | --- |
| `一键启动.bat` | 命令行拉起服务，就绪后自动打开浏览器；日志在 `logs\backend.log` / `logs\frontend.log` |
| `旅鸢桌面版.bat` | 用 Electron 打开桌面窗口；首次运行会自动安装前端依赖与 Electron 运行时 |

- 后端默认带 `--reload`（改 Python 自动重载），前端 Vite 自带 HMR（改 Vue 自动刷新）
- 服务已经在跑时，两个入口都会**复用**而不会重复启动
- **停止统一使用 `停止服务.bat`**（用于结束监听 18010 / 5180 的进程）；关闭桌面版窗口不会停止服务
- 「一键启动」会先清理上一次启动的服务（修改代码后直接双击即可）

```powershell
cd <项目根目录>
.\scripts\start.ps1              # 清理旧进程并重启（默认）
.\scripts\stop.ps1               # 停止服务
.\scripts\smoke.ps1              # 跑测试 + 契约摘要
```

依赖：Python 3.11+、Node 20+，以及根目录的 `local.env`（DeepSeek / DashScope / 高德 的 key，**不入库**）。
