# 演示账户 · 真实前端操作演示

> 上一版把演示做成了独立画布，等于另做了一套模仿界面。这一版改成**在真实前端上操作**：真的鼠标指针会移动、真的点真实按钮、真的在真实输入框里一个字一个字打字；页面就是产品本身的页面，数据来自真实后端。

---

## 1. 怎么进入与怎么操作

| 项 | 说明 |
| --- | --- |
| 进入 | 右上角头像 → 用户菜单第一项「演示账户 · 全流程演示」 |
| 过程 | 进入后自动开始第 1 步；鼠标指针出现在页面上，移动到目标元素并点击 |
| 打字 | 到了输入框的步骤，会在真实输入框里逐字打出编排好的话，再点「发送」 |
| 下一步 | 底部控制条的「下一步」；或点页面空白处（只响应真人点击，程序自己的点击不会误触发） |
| 自动播放 | 底部「自动播放」，每步执行完等 1.4 秒继续 |
| 重播本步 | 底部「重播本步」，可反复演示同一步 |
| 退出 | 底部「退出演示」，指针隐藏，回到正常使用 |

端口与产品一致：`_lvyuan` 是 http://127.0.0.1:5180/ ，`_sinanlike` 是 http://127.0.0.1:5280/ 。

## 3. 机制

| 文件 | 作用 |
| --- | --- |
| `frontend/src/demo/driver.ts` | 驱动引擎：指针移动（缓动）、点击（真实派发 click）、逐字输入（写 value + 派发 input，Vue 的 v-model 能收到）、滚动到可视区 |
| `frontend/src/demo/DemoCursor.vue` | 指针与点击涟漪，`z-index` 最高，`pointer-events: none`，不挡真实操作 |
| `frontend/src/demo/DemoBar.vue` | 底部控制条：阶段、步数、本步说明、上一步 / 重播 / 自动播放 / 下一步 / 退出 |
| `frontend/src/demo/beats.ts` | **剧本**：15 步，每步写「点哪里、打什么字」 |
| `frontend/src/demo/store.ts` | 播放状态与推进逻辑；空白处点击推进只响应真人点击（`event.isTrusted`） |

找元素用文本匹配（`clickText`），比写死 CSS 选择器稳：按钮文案变了演示还能跑。

---

## 4. 与随机性的关系

演示跑在真实后端上：抢单、订单状态、交付物、评分、画像写回都是真实链路，AI 回复也是真实生成。也就是说这次演示看到的内容会随真实数据变化——这是产品本身的行为，不再有第二套数据。

如果某一步的真实条件不满足（例如待接单列表为空），该步会记一条 `[demo] 找不到可点元素` 的警告并继续下一步，不会卡死整段演示。

---

## 5. 怎么改

只改 `frontend/src/demo/beats.ts`：加一个 `{ id, phase, title, action, run }`，在 `run` 里用 `d.clickText(...)` / `d.type(...)` / `d.sleep(...)` 写操作即可。改完刷新页面就生效。

---

## 6. 剧本接口（真页面 + 定稿内容）

页面、组件、路由、交互全部是产品本来的，不改一行页面代码。演示账户打开时，`frontend/src/demo/fixtures.ts` 会挂一个 axios 拦截器，把**几个由 AI 现场生成的接口响应**换成写好的剧本：

| 接口 | 剧本内容 |
| --- | --- |
| `GET /threads/C1.1`、`POST /threads/C1.1/messages` | 掌握度固定为教学 42 / 实战 0 / M3；老师最后一句话换成编排好的 M1–M5 讲解 |
| `GET /practice/im/sessions` + `POST /practice/im/sessions/{id}/messages` | 对方回复按队列替换：客户确认日期与忌口；地接社回 8 人 4 天明细与 12,800 小计；酒店回外滩店只剩 4 间双床、可免费取消 |

其余接口全部走真实后端：消息中心派单与抢单、订单列表与详情、产出与投递、评分复盘、画像写回。也就是说：**会话内容是定稿的，业务状态是真实的**。

实现上只做了一件事：拦截响应后改写里面的文本字段（`content` / `mastery`），不重建数据结构，所以页面不会因为剧本而报错。退出演示时拦截器自动卸载，恢复真实 AI 回复。
