## 2. Vibe coding 工作约定（团队统一执行）

1. **契约先行**：改任何功能前，先把数据结构/枚举/接口写清，再让 AI 生成实现；禁止「先写再补契约」。
2. **垂直切片**：每个功能以「能跑通的最小闭环」交付，不做只完成一半的横切功能。
3. **单一数据源**：同一概念只允许一处定义（技能点、Rubric、状态、难度参数），杜绝两份描述。
4. **关键判定人工把关**：门控、算术、证据链、状态迁移必须人 review，AI 不能自决。
5. **每步可验证**：每个交付物配一个「验收脚本 + 样例数据」，AI 改动后能一键回归。
6. **内容与代码并轨**：内容用表格（xlsx/csv）维护、导入系统，改内容不改代码。
7. **进度即文档**：维护一份 progress/handoff，记录已完成、待办、已知问题、启动方式。
8. **小步提交**：一个切片一个提交，提交信息写清「改了什么 + 怎么验证」。

## 4. 里程碑详情

### M0 · 地基（骨架 + 契约 + 语音）

- **目标**：新库能跑起来，数据契约与状态机骨架就位，实时语音移植完成。
- **关键交付物**：
  1. 新仓库骨架（前后端 + 运行脚本，参考旧库启动方式）。
  2. 数据契约 v0：技能点 / Rubric / 状态 / 画像 / 证据链 / 交付物的表结构与枚举（PRD 第 5、17 章）。
  3. 状态机骨架 S0–S12（含门控布尔、时限、回退），先不接业务（PRD 第 3 章）。
  4. 实时语音移植跑通（PRD 第 22 章第 1 项）。
- **验收标准**：能创建一次演练实例；状态机能按门控推进/回退；语音可连续对话 3 轮不中断。
- **依赖**：无。

### M1 · 首个垂直切片（S2 首呼）

- **目标**：用一个最小闭环证明「对话→交付物→评分→证据→画像」成立。
- **关键交付物**：
  1. 客户 Agent 对话（S2 场景，支持不耐心、需求分批释放）。
  2. 需求单交付物 + 结构化字段（PRD 第 4 章 S2、第 5 章需求表）。
  3. Rubric 评分（含证据引用）+ 覆盖校验（PRD 第 18、19 章）。
  4. 画像写回：S2 相关技能点（C1.1/C1.2/C1.3/C2.1/C2.2）的 M1–M5（PRD 第 17 章）。
- **验收标准**：跑完一次 S2，能产出需求单、评分每条带证据、画像更新，且整场可回放。
- **依赖**：M0。

### M2 · 判断与检索底座

- **目标**：把「三层判断」和检索能力做成通用底座，供所有 Agent 复用。
- **关键交付物**：
  1. 三层判断框架：硬编码规则层 / 结构化判断层 / 生成层，边界与接口固化。
  2. BM25 多路召回（新知识库）+ LLM 重排（PRD 第 22 章第 5 项）。
  3. 引用链组件：生成资料附来源 ID + 「参考来源」章节（PRD 第 22 章第 4 项）。
  4. 六帽审查框架（改造 Prompt）作为资料交付质量闸门（PRD 第 22 章第 3 项）。
- **验收标准**：检索结果可复现；任一份生成资料能列出并反查来源 ID；六帽能给出「合格/需修改」判定。
- **依赖**：M0。

### M3 · MVP 主干（8 步主线）

- **目标**：端到端跑通一单（可丢单、可成单）。
- **范围**：抢单接单 → 首呼需求挖掘 → 资源询价 → 行程方案 → 分项报价 → 客户反馈修改 → 行中突发事件 → 行后结算（PRD 第 11 章）。
- **关键交付物**：
  1. 资源方 Agent（报价/库存/档期/冲突，数值由规则给）。
  2. 6 类交付物 + 对应门控与评分。
  3. 导演埋点：A/B 考点注入 + 覆盖校验（PRD 第 19 章）。
  4. 事件注入：行中突发事件（车坏/超售/无票/降级）。
- **验收标准**：能完整跑完一单，6 类交付物齐全，门控与回退可触发，覆盖度可计算。
- **依赖**：M1、M2。

### M4 · 闭环（画像-难度-资料）

- **目标**：让「评分 → 画像 → 难度 → 学习资料」形成闭环，且可追溯。
- **关键交付物**：
  1. 61 技能点全覆盖评分 + 能力值聚合（PRD 第 17 章）。
  2. 掌握度 M1–M5 + 难度联动（M1 补救 / M2–M5 递增加压 + 整单合成规则，PRD 第 20 章）。
  3. 覆盖校验落地：未覆盖不更新画像（PRD 第 19.4 节）。
  4. 学习资料生成 Agent：模板「反例→后果→正例→知识点」+ 练习（PRD 第 21.3 节）。
  5. 追溯链：实例→步骤→消息→动作→锚点→知识点（PRD 第 20.6 节）。
- **验收标准**：一次实战后画像变化可追溯到具体证据；下一单难度按画像变化；生成资料引用了来源。
- **依赖**：M3。

### M5 · 入境叠加

- **目标**：在通用流程上叠加入境变量。
- **关键交付物**：
  1. C8 跨文化入境游沟通维度（7 个技能点，PRD 第 17.3 节）。
  2. 国别文化数据（6 国：沟通风格/实操红线/推荐目的地，PRD 第 15 章）。
  3. 多语种首呼与行程、签证/免签政策条目。
  4. 入境文化/政策 Agent 的 IN-01～IN-07 任务。
- **验收标准**：入境单能跑通，红线命中能被质检识别并扣合规分。
- **依赖**：M4。

### M6 · 打磨与演示

- **目标**：可演示、可评审。
- **关键交付物**：
  1. 前端设计语言还原（蓝白 + 国风山水/云纹，PRD 第 22 章第 2 项）。
  2. 复盘报告 + 能力雷达图 + 掌握度变化。
  3. 演示脚本与样例数据。
- **验收标准**：能完整演示一单；复盘报告可展示证据与画像变化。
- **依赖**：M4。

## 6. 建议技术栈（轻量、沿用旧库已验证的部分）

| 层 | 建议 | 说明 |
| --- | --- | --- |
| 后端 | Python + FastAPI | 沿用旧库验证过的栈，语音/检索可直接接 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 内容量太大（61 技能点 Rubric） | 阻塞 M3/M4 | 先做 MVP 子集，分批评审；内容与代码并行 |
| 生成式模型越界做判定 | 幻觉、不可审计 | 三层判断隔离；门控/算术/证据链硬编码；关键判定人工 review |
| AI 生成代码结构发散 | 维护成本高 | 契约先行；单一数据源；每步可验证 |
| 评分不准 | 画像失真 | 小样本人工标注校验；低置信度升级；覆盖校验兜底 |
| 依赖旧库 | 继承技术债 | 只移植 5 项资产；验收红线：禁止引用旧 data/knowledge/mastery |
| 实时语音依赖外部服务 | 演示中断 | 保留文字通道降级；密钥/网络预检 |
| 入境政策/文化口径不准 | 合规风险 | 标注「待访谈验证」；政策条目要求来源 |

- 导演 Agent 监听事件 → 按难度/覆盖需求决定是否注入突发事件。
- 与既有 OR-07 / 第 21.1 节导演埋点合并实现。

### 10.4 不做什么（明确边界）

- 不为「技术亮点」而堆框架（见 PRD 第 24 章、D-014）。

### 10.5 人工校准集（评分公信力保障）

> 对应 PRD 第 25 章、DECISIONS D-015。

| 任务 | 归属 | 验收 |
| --- | --- | --- |
| 校准集抽样与标注 | M3 起 | 按 61 技能点分层采样；双人独立标注；算一致性 |
| 建评分基线 | M4 前 | M 档一致率 ≥85%、证据准确率 ≥90% |

红线：评分 Agent 未经校准集验证，不得进入主链影响画像。

### 10.6 MCP 落地口径（补充）

- **先搭 MCP 框架**（接口/协议层），**demo 用虚拟数据填充**。
- 真实接口（携程等）后续按同一接口接入，上层不改。
- 接入方式（自建轻量 vs 现成 SDK）在 M2 前定。
